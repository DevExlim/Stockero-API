# Getting started

## Before making requests

The current API is intended for the PokeStock Watch website. A caller must:

1. Sign in through PokeStock Watch with Discord.
2. Belong to the configured Discord server.
3. Hold the paid-member role.
4. Send the secure session cookie with each protected request.

Requests made from the PokeStock Watch website automatically include the session cookie.

## Recommended request headers

```text
Accept: application/json
X-Request-Id: <a unique UUID generated by the client>
```

JSON mutations also use:

```text
Content-Type: application/json
X-CSRF-Token: <token issued by the website session>
```

## Response headers

Stockero responses include:

- `X-API-Name: Stockero API`
- `X-Request-Id`: the request identifier to provide when requesting support
- `Cache-Control`: endpoint-specific caching instructions

## Response conventions

Successful list and object responses place their result in `data`. Paginated responses also include `meta`.

```json
{
  "data": [],
  "meta": {
    "count": 0,
    "nextCursor": null
  }
}
```

Never place the Discord bot token, Discord client secret, database credentials, Google server key, session cookie, or CSRF token in client logs or public documentation.
